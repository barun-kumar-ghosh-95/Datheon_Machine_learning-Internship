# Predictive Customer Churn Classifier

A machine learning project that predicts whether a telecom customer is
likely to leave the service (churn) using the **Telco Customer Churn**
dataset. This project compares **Random Forest** and **XGBoost**
classifiers and evaluates their ability to identify customers who churn.

## Project Overview

Customer churn prediction helps telecom businesses identify customers
who may leave and take proactive steps to improve retention.

This notebook follows an end-to-end machine learning workflow, including
data inspection, cleaning, exploratory data analysis, preprocessing,
class-imbalance handling, model training, and evaluation.

## Objectives

-   Understand the customer dataset and its features.
-   Clean the data and prepare it for machine learning.
-   Explore patterns and relationships associated with customer churn.
-   Handle class imbalance using SMOTE.
-   Train Random Forest and XGBoost classification models.
-   Compare model performance using classification metrics and
    visualizations.
-   Examine the most influential features using feature importance.

## Dataset

**Dataset:** `Telco-Customer-Churn.csv`

The dataset contains **7,043 rows and 21 columns**. It includes customer
information, subscribed services, account details, billing information,
and the target column `Churn`.

The target variable has two classes:

-   `No` --- the customer did not churn.
-   `Yes` --- the customer churned.

The dataset contains 5,174 non-churn customers and 1,869 churn
customers, making it an imbalanced classification problem.

## Project Workflow

1.  **Data loading and inspection** --- load the CSV file and inspect
    its shape, columns, data types, sample records, and missing values.
2.  **Data understanding** --- review descriptive statistics and the
    distribution of the target variable.
3.  **Data cleaning** --- create a copy of the DataFrame and convert
    `TotalCharges` to numeric. Invalid or blank values are converted to
    missing values.
4.  **Exploratory Data Analysis** --- visualize churn distribution and
    explore churn in relation to tenure, monthly charges, and contract
    type.
5.  **Train-test split** --- split the data into training and testing
    sets using stratification.
6.  **Preprocessing** --- impute missing numerical values using the
    median, scale numerical features, impute categorical values using
    the most frequent value, and apply One-Hot Encoding.
7.  **Class imbalance handling** --- use SMOTE within the training
    pipeline to generate synthetic minority-class samples.
8.  **Model training** --- train Random Forest and XGBoost classifiers.
9.  **Model evaluation** --- compare accuracy, precision, recall,
    F1-score, and ROC-AUC.
10. **Visualization and interpretation** --- plot ROC curves and
    confusion matrices, and inspect the top feature importances.
11. **Cross-validation** --- evaluate ROC-AUC using stratified 5-fold
    cross-validation.

## Models

### Random Forest

An ensemble learning algorithm that combines predictions from multiple
decision trees to perform classification.

### XGBoost

A gradient-boosting algorithm that builds decision trees sequentially,
with each new tree helping correct errors made by previous trees.

Both models are trained using preprocessing and SMOTE steps in an
imbalanced-learn pipeline.

## Evaluation Metrics

  ---------------------------------------------------------------------
  Metric                             What it measures
  ---------------------------------- ----------------------------------
  Accuracy                           Overall proportion of correct
                                     predictions

  Precision                          Proportion of predicted churn
                                     customers who actually churned

  Recall                             Proportion of actual churn
                                     customers correctly identified

  F1-score                           Harmonic mean of precision and
                                     recall

  ROC-AUC                            Ability to distinguish churn and
                                     non-churn customers across
                                     classification thresholds
  ---------------------------------------------------------------------

## Important Notes

-   The `customerID` column is excluded from model features because it
    is an identifier.
-   `TotalCharges` is converted to numeric before model training.
-   The train-test split is performed before fitting the preprocessing
    and resampling pipeline.
-   SMOTE is applied inside the training pipeline, not to the held-out
    test data.
-   The default classification threshold used for predictions is 0.50.
-   The notebook's results depend on the actual run and should be
